I read the spec, the ticket, and the four `$(cat …)` sites in `docs/devteam/scripts/devteam.mjs`. Three are named by the ticket: 12704 `recover`, 12921 `legacyRecover` and 15809 for the worker and planner. The fourth is the operator at 13345, which is out of scope. I also read how the prompt file is written (15746), `knowledgeFor`/`knowledgeBlock`/`scopeContext`/`SCOPES`, `parseLines`/`integrity`/`fold`, `threadsFixture.hand` in `test/lib/kit.mjs`, and the argv assertions in `test/recovery.test.mjs` and `test/machine.test.mjs` (claudeCalls). The fix is sound for fresh launches. `shq` quotes the message safely, `path.resolve` covers relative paths, the message names no harness, and none of the supervisor resume assertions change. The planned test can produce a prompt over 200 KB. Scope `all` matches any context, so a planner gets it. A supervisor-written `new` knowledge line with `status: accepted` folds into an accepted object, and `integrity` lets it through. The `given` list stops at 60 ids, so the act line stays under LINE_MAX. Three details need care, listed below. The main problem is how the spec reads "resume paths unchanged". Site 15809 is one line that serves both fresh launches and `--resume`. Resume rewrites the prompt file with the full knowledge block and still passes it through `$(cat …)`. So the incident this ticket exists for (app-128) comes back on the first routine relaunch of any worker whose prompt is over 128 KB. That contradicts the ticket title ("can never exceed"). The literal "unchanged" reading is defensible, but leaving the gap is not.
