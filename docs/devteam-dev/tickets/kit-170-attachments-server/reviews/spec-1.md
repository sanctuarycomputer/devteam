## Values and refusals

- **P1 Harness-agnostic:** The supervisor gets a bracketed paste of paths. Claude Code turns image paths into attachments. Codex and OpenCode get plain paths, which degrades cleanly to "a path", the same as a pane drop. Passes.
- **P2 Nothing project-specific:** The `<project>` folder comes from the checkout's path, not from settings. Passes.
- **P3 Decide and report:** The spec decides `.jpeg`, the folder naming and the modes itself, which is fine. `.jpeg` departs from the done-when's literal text and should be recorded as a ruling (S3).
- **P4 Owner-only rulings:** None needed. There are no one-way doors.
- **P5 Adversarial review on authority:** risk: high, with two final reviewers. The spec lists the cases they will try. This review tried the box route's position relative to the session and Origin checks (sound: the route sits in the `if (port)` branch after both), DNS rebinding (the Host check covers it), a cross-site GET (crossSiteOk on the box, Sec-Fetch-Site on the laptop), TOCTOU between realpath and open (no writer other than the owner's user or `gw` can change the root), and a split body read (A5's never-sent body). Passes, with S1, S2 and S4 to fix.
- **P6 Keep it simple; agents trusted not to forge:** The design is simple. It doesn't yet name what it leaves undefended (S6).
- **R1 No self-widening of authority:** Not crossed. `--files` is accepted only on the owner's own answer and turns, and refused with `--defaulted`, `--from-chat` and `--from-turn`. A file adds no authority, and paths outside the folder are refused.
- **R2 No codespeak to the owner:** The refusal reasons are plain words ("this machine has no folder for dropped files: …", "too long with its files"). On a box, some refusals are not `{error}` JSON (S1), so the page must show their text as the reason.
