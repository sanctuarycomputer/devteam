Spec compliance: ❌ Steps 1-7 and A4-A7, A9 (laptop half) and A10 are met. Step 8's "anything else is 500" is not: a failure after the body has been fully read gets no answer at all (T2-1).

What was checked (one focused check per named risk):
- **Refusals before the body.** I read `receiveLaptopUpload` top to bottom. Nothing touches `req` before the `for await` at the end of the try: the box, Origin/Sec-Fetch-Site, declared-size, root, sweep and total checks all answer through `refuse`, with `connection: close`. A5 holds the body back (`flushHeaders`, 1 MB declared) and fails on a 2 s timeout, so a check moved after a read would make it time out. The implementer reports a mutation run of exactly that. The suite passes at 3ac257ff (9 pass, 1 skipped as the brief says: this machine is a box).
- **Origin / Sec-Fetch-Site / Host.** These are strict `!==` comparisons against `http://${req.headers.host}` and `'same-origin'`, after the dashboard's own exact Host list. There is no prefix match and no case folding. Node joins a repeated Origin with `, `, so it can't match. The check runs before `laptopUploadsDir`, `uploadRootOk({make})` and the sweep. A5 checks only that no upload folder is under the root, which holds even if the root had been made (T2-4).
- **Override.** `uploadLimits()` returns the constants unless `boxFilesOff()` (the function) is true. MAX/TOTAL/STALL use `Math.min`, FREE uses `Math.max`, and only `/^[1-9]\d*$/` safe integers count. It sits after `/* upload rules end */`. The A7 never-raises test and the gate test (skipped on a box) cover it.
- **Sweep.** It touches only `UPLOAD_FOLDER` names that are dirents of directories, then lstat directories owned by this uid. A fresh `.part` is kept and a stale one removed, and the `.part`'s own mtime decides. The race in the report is real. Within one process: the sweep gets a snapshot `Set` of the receiving keys, not the live Map, so an upload that starts during an earlier sweep can lose its just-made empty folder (T2-2). Across processes (another dashboard for the same project): the "no file" rule has no age guard, so it removes a folder another dashboard made a moment ago. That breaks Edge cases "the sweep never removes a folder being received" and the spirit of S7 (T2-3). It is not silent loss, but because of T2-1 the result is a hang rather than the 500 the report claims, when the folder goes after the `.part` is opened.
- **Pending bytes.** `uploadsReceiving.set` happens only after the 507 total check. Everything after it is inside try/finally, and `finally` deletes the entry and clears the stall timer on success, a 413 mid-stream, a stall, ENOSPC and any other error.
- **Modes and root.** `mkdir` 0700 for `~/.devteam`, `uploads`, the root and the folder; `.part` is opened `wx` 0600. The root is refused when lstat shows a symlink, a non-directory, another uid, or `mode & 0o022`. A root that is a symlink passes `mkdirSync({recursive})` and is then refused by lstat. A7 checks this, and checks that the link's target stays empty.
- **Tests.** No mocks: a real dashboard, real http, real files. HOME is a `mkdtemp` folder, and `t.after` stops the dashboard and removes the base. The gate test unsets `DEVTEAM_BOX` but keeps the throwaway HOME. Nothing touches the real HOME or `/data/uploads`.
