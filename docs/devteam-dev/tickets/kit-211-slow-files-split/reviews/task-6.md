The same tests at the head start the same number of children and leave 0.
- The pool exclusion is justified. `runNode` blocks until the runner writes its exit file, or breaks once the runner is dead, so a runner that took a command is gone before the call returns. What is left is idle slots: WARM = 3, which matches `pool 3` in every pane-question run. Each slot exits within 50 ms of its parent dying. A real leftover can't hide there: a used runner's command runs in the runner's own process, and anything it spawns has a different cmdline.
