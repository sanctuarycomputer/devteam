A pane that prints the dialog therefore raises nothing today. Check 1 would fail without the change. The proposed anchored forms match the captured lines once `paneWaitingIn` trims them: `Quick safety check: …` and `Yes, I trust this folder` are both line-initial, and neither starts with a `PANE_CODE` prefix. The `limit` pattern does not match the dialog, and `PANE_BUSY`'s lookbehind keeps `Enter to confirm · Esc to cancel` from counting as busy. `lines.find` takes the first match from the top, so the detail is the `Quick safety check:` line as check 1 expects. About 10 to 13 non-empty rows fit in the bottom 15, even after wrapping at 40 to 80 columns. `Do you trust the contents …` and `Do you trust this folder` also cover the Codex and Gemini wordings, which fits P1.

Check 2 also fails without the change. The stand-in agent shows the dialog unless the hook already ran, and the negative `metrics` assertion comes after the agent has recorded its start, so it is not vacuous. Putting the hook after `seedWorktree` and before the lock and the typed lines means it runs synchronously before the agent starts on every path: fresh, `--resume`, `--replace-agent` and `--if-gone`. Warn-and-continue is sound because the finding is the fallback. The supervisor's `resendLostEnter` already holds off on a pane that shows `Enter to confirm`, so the dialog's default `No, exit` never gets an Enter, with or without this change. Widening the prompt pattern also makes `limitStop`'s `otherPrompt` true for a trust dialog. That is correct, because a dialog is not a limit stop, though the spec does not say so. The files fit within touches. No other doc lists every setting; quality.md:130 lists the owner settings and is in touches. supervisor.md:132 is not an exhaustive list (it already omits `resume_command`), so it needs no edit.
