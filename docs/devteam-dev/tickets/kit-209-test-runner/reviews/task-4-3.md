- Adversarial check of `freeLocks`. It frees only a lock whose trimmed content is one of the named pids, and only when `isAlive` is false. EPERM counts as alive. A zombie counts as dead, which is correct because a zombie runs no exit hook and its pid can't be reused while it is a zombie. A `ps` that fails yields `''` and so counts as alive, the safe side. A pid reused between the kill and the free shows as alive, so its lock is kept. The one unguarded window is between `readFileSync` and `rmSync`. Another lock could take the file's place there only after a third party deleted it as stale (dead owner and over an hour old) and a fourth claimed it, all within microseconds. `lib/ports.mjs`'s own exit hook has the same read-then-remove shape. I accept it as theoretical.
- `same()` for SIGCONT is right. A stopped pid's ppid changes only when its parent exits. So "under the recorded parent, or the recorded parent exited" is the identity test the kill uses, minus `T`. An orphan resumed under that rule could in theory be a reused pid, but a SIGCONT to a running process does nothing.
