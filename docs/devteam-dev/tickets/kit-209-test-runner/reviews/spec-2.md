| F2-1 | Minor | ticket notes ("kills process trees on shared machines"); spec §Watchdog step 1, "a stopped process can't exit, so its pid can't have been reused" | spec.md §Watchdog and cleanup, step 1 | The safety argument isn't airtight. When a parent exits, the kernel sends SIGHUP and then SIGCONT to any process group it orphans that still holds stopped members: a group in the same session but a different pgrp, as made by `setpgid` without `setsid`. So if a parent in the kill set is SIGKILLed before such a child, the child can be resumed, exit, be reaped by init, and see its pid reused before its own SIGKILL is sent. Node's `detached` (setsid) children and same-group children don't hit this, so the window is tiny, but the spec asserts an invariant the algorithm doesn't guarantee. Say that the SIGKILLs go deepest-first (the reverse of stop order, children before parents, root last), so no stopped group is ever orphaned mid-kill, and have `stopTree`'s unit test assert that order. | fixed in plan.md, Spec amendments |
| F2-2 | Minor | done-when 5 ("last test finished: <name>") | spec.md §Edge cases, TAP bullet | "The deepest last `ok`/`not ok` line" is ambiguous, and read literally it gives the wrong name. Suppose test A has subtests and finishes, then test B (no subtests) finishes, then the file hangs. The deepest-last line is A's last subtest, not B. The wrapper exclusion (description equal to the file's path) already handles Node 18/20, so "deepest" isn't needed. Say "the last `ok`/`not ok` line in output order, at any depth, other than a per-file wrapper's". | fixed in plan.md, Spec amendments |
