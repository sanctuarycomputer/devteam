| P2-2 | Important | ticket notes ("kills process trees on shared machines"); plan Global Constraints ("Kill only pids this walk stopped and still sees stopped; never a group by number"); spec §Watchdog step 1 rationale (pid reuse) | plan.md Plan review 1 changes, P1-1 (`runRunner` teardown "in a `t.after` hook either way") | The teardown runs after every test. | P2-3 | Important | spec §Watchdog step 1 ("SIGKILL exactly the pids this walk stopped that the final snapshot still shows stopped"); spec §Kill only pids this walk stopped; plan Global Constraints (same) | plan.md Plan review 1 changes, P1-3 ("plus any present whose parent in that snapshot is a stopped pid") | This clause SIGKILLs pids the walk never stopped. It contradicts the spec's kill rule and the plan's own constraint, and there is no spec amendment for it. It is also unsafe. Such a pid is running, not stopped. A stopped parent normally keeps a dead child as a zombie, but a parent that ignores SIGCHLD (`SA_NOCLDWAIT`, as some shells and daemons do) has its children reaped by the kernel.
