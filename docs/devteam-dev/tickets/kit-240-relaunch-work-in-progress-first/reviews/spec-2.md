Verified: with `timeout` and `killSignal: 'SIGKILL'`, spawnSync returns `status: null`, `signal: 'SIGKILL'` and `error.code: 'ETIMEDOUT'` (checked with a 0.5 s `sleep 5`). `worktree_setup` runs on every `--resume`, because makeSession calls `seedWorktree(wt)` with setup on (devteam.mjs:16254). That call comes before the launch lock and `new-window`. So a child killed during setup leaves no window, and the next tick finds the session still gone. A kill between `new-window` and the launch act leaves a window with no agent in it, which `sessionsToRelaunch` then skips. Today's design has that same narrow case, and the fix doesn't make it worse.
