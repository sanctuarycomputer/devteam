The plan covers every spec item and done-when with a task: the contract comments (T0), `boxImage`, the `image` field and the start line (T1), the fallback's `down` (T2), `boxLine` and its wiring (T3), and the `machine status` line (T4). Every file is inside `touches`, the TL;DR has six bullets, and most mutants would be caught: dropping the token check (the escape cases in T1, T3 and T4), skipping `hubSeen = null` (T3's catch regex), a `createGateway` that ignores `opts.env` (the `/box.json` image test), and reading the variables anywhere else (the count assertion). I checked the code the plan relies on. `gateway()` spreads `extra` into `createGateway`'s opts, so `{ env }` reaches it. `serve` can write the line before `listen`. `el` sets text with `textContent`. `findBox` runs before the first `draw`. `lib/kit.mjs` already removes every `DEVTEAM_*` variable from `process.env`.

Four steps fail as written, though, and an implementer hitting them could easily weaken the test to get past them. T0's own comment breaks T1's count assertion. The constant name T1 picks is already taken in `createGateway`. T3's R2 regex rejects the plan's own expected texts. T3's array assertions compare arrays across vm realms.
