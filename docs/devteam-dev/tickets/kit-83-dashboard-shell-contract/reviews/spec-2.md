Neither page uses `peek-open`, `threads-open`, `no-shell` or `shell-ring` today, and index's only keyframe is `spin`. The `.no-shell` boundary is sound CSS. `:not()` takes its argument's specificity, and a `:where()` argument has none, so `:where(.shell) X:not(:where(.no-shell, .no-shell *))` weighs the same as `X`. Complex selectors inside `:not`/`:where` are Selectors 4, which every engine CI's Chrome and the owner's browsers support. A pseudo-element stays legal as long as the `:not` comes before it, which the spec says. The boundary also covers the subject being the `.no-shell` element itself (as with `.page > :first-child`). The adoption order fits the table: kit-87 owns the frame and puts `shell` on `<body>`, and kit-88 and kit-89 each lift `no-shell` from their region. The fence stops block rules from matching. It does not stop inheritance (F2-3). The one form defect is that the frame's state hooks don't fit the stated selector form (F2-1). No new Critical, so no pass 3.
