The F2 fixes hold. The landing rule (spec.md:103) is now the design's, word for word in substance: main holds the edit's value, and a `merge-chore` act with refs `chore-settings` is newer than the edit. Nothing reads an old head, which closes F2-2 (squash, rebase or a fresh clone can no longer flip a landed override back to "Saved"). The no-op override now counts, and the spec says so and gives the label, which closes F2-1's contradiction. Done-when 4's "not for an edit in an unmerged worktree" holds: an unmerged edit whose value differs from main's never counts, and one whose value equals main's counts only after a later settings merge (F3-1). The CLI's port now comes from the last `started on http://127.0.0.1:<port>` in `run/dashboard.log`, else `run/dashboard-port`. I checked that every listen logs that line (devteam.mjs:15333), that the logger rotates only at start (before writing that start's line, devteam.mjs:11914), and that `pickDashboardPort` writes no file when pinned (devteam.mjs:11948-11951), so the order the spec picks is the one that works for a pinned dashboard. The validate rule now checks the act's shape (key name pattern, value 1 to 20 or null, no `artifact` or `tree`) and leaves the allowlist to the writers. That keeps old acts valid if the allowlist narrows, and it still refuses a malformed value. The CLI and the route still refuse off-allowlist keys, as done-when 2 needs.

The no-op override is labelled "Set by the supervisor (you asked for N)", which is true: main's value is the supervisor's deliberate choice, and nothing the owner didn't choose is shown as theirs. Widening validate to the act's shape lets no forged act through: the fence is still `OWNER_ACTS` plus `ownerWriter`, plus the gateway's proof on a box. No refusal is crossed.
