## What I tried

1. **A skipped or cancelled job reading as green.** All 16 jobs come from a static `include` with no job-level `if`, so none can be skipped. A cancelled run is real evidence here: run 43765291011, superseded by the next push, has all 16 kit jobs `completed/cancelled` and `tests` `completed/failure` (it ran because of `always()`, and it is red, not skipped). The `needs` step fails on any result other than `success` (`skipped`, `cancelled` and `failure` all fail it) and on an empty `needs`. devteam-ci-green.sh fails a run whose conclusion isn't `success` or that has any job that isn't `completed/success`. checksRefusal fails any bucket other than `pass`, so `skipping`, `cancel` and `fail` all fail it. **Not broken.**
2. **`tests` passing while a shard fails.** fail-fast is false, and `needs.kit.result` is `success` only when every matrix leg succeeded. Run 43765317351 (deliberate `exit 1` in `kit (18, chain)`) shows that job `failure` and `tests` `failure`. A step timeout (11 min) fails its job, and the job timeout (12 min) cancels it; either way `needs` is red. A re-run of failed jobs re-runs `tests` against the latest attempt's results. Stale artifacts from an earlier attempt could only make coverage pass for a job that died before uploading, and that job's failure still fails `needs`. A failed list or upload step (`if-no-files-found: error`) fails its own job. run.mjs exits 1 on any file failure or timeout. With an empty plan it prints `no files` and exits 0, which can't hide a file, because coverage requires every file. **Not broken.**
3. **A new file landing in no shard.** In a scratch copy of `test/`, I listed every matrix row with `run.mjs --list` and ran the coverage step extracted with the ticket's own awk. A dotfile gives a safe red (F1b-2). **Every way a file could be lost is caught.**
4. **Shard drift.** `shard()` deals each file once, to the lightest shard. The order is by weight, with ties broken by name. Both shards of a major compute the same deal from the same checkout, the same sorted `readdirSync` and the same timings.json. The list step and the run step share `RUN_ARGS`, and planRun doesn't read `--concurrency` or the environment. Adding 10 unweighted files still gave each file exactly once per major (85 files, exit 0). **Drift costs balance only. No file is lost or doubled.**
