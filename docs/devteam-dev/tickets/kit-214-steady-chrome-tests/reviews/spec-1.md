What was checked on the box (Node 22.23.4, /usr/bin/chromium; scratch child test files, each under `timeout`):
- Class A holds. With `openChrome()` and a page open, Chrome SIGSTOPped, a throw and then `t.after(() => c.close())`, a second test in the file shows `# pass 0`, `# fail 1`, `# cancelled 1`, "Promise resolution is still pending but the event loop has already resolved". This happens whether the page socket is left open, closed before, or closed after. Adding only `proc.ref()` at the start of `close()` in a scratch copy gives `# pass 1`, `# fail 1`, `# cancelled 0`, and the group is gone. The root cause and the fix are right.
- Class B holds. On Node 22, `t.after` hooks run in the order they were registered, and the first one that throws stops the rest: the second hook never ran, `failureType: 'hookFailed'`.
- Class C holds. The page's `ready` handler returns at once when `TS.ready` is already true (index.html:5834). So the readies cause no draw and no resolve, and the draws counted come from poll and threads redraws. `__still()` holds both.
- Class D's gate goes through PATH. `tmuxAsync` is `execFile('tmux', …)` (devteam.mjs:14882). The hello child's tmux calls are `capture-pane`, which passes through. Held lines are flushed only by the tick or a supervisor-role path (devteam.mjs:2834, 14088), and the dashboard runs neither.
- The mechanical teardown conversion is safe. The four small files and dashboard.test.mjs use only the plain rm / stop / close / `p.close` pattern, or an `undo` stack.
