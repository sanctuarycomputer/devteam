The bad-fixture error regexes match the messages `schemaErrors` actually produces. But four things block. First, the committed plan.md is corrupted: a `$`+backtick replacement pasted the whole file back into itself six times, so it is 613 lines with seven TL;DRs and repeated Task 1 bodies, and it lost the closing `$` of four patterns. Second, the TL;DR has eight bullets, which `tldrGap` refuses at `approve-plan`. Third, T2's implementation step says the 2FA code is 6 digits, which contradicts the spec and the plan's own interface. Fourth, done-when 3's test leaves out several guard rules the spine lists.
