| F1 | Critical | done-when 1, done-when 3; spec "On `--test-timeout`" bullet and acceptance check 1 | spec.md "What was found", last bullet; acceptance 1 | The spec says the flag "on Node 18 to 22 caps each whole test file's process", and plans to pass `--test-timeout=600000` to every `node --test` step on every matrix version. Node 18 does not have the flag. A probe on 18.20.4 (`node --test --test-timeout=3000 x.test.mjs`) prints `node: bad option: --test-timeout=3000` and exits 9. The flag first shipped in Node 20.11 and 21.2, so CI's newest Node 18 most likely rejects it as well. As written, every `kit (18, chain)` and `kit (18, rest)` job fails at its first test step, and done-when 3 ("no other job slows", every job passes) cannot be met. The spec must leave the flag out on 18, or use another bound for 18 such as a `timeout`-wrapped step. It must also correct the measurement claim. | |
| F2 | Important | done-when 1 ("a hung test fails in minutes and its name is in the log"); acceptance check 1 ("A file still running after 10 minutes is killed and named in the log") | spec.md "What was found", last bullet; acceptance 1 | On Node 24, `--test-timeout` does not end a file whose tests have all finished but whose process stays alive. That is exactly the failure mode the spec diagnoses, where a leaked child pipe keeps the file alive. Probe: one test that throws in its first `t.after` and leaves a `setInterval`, plus one test that spawns a detached child with piped stdio. The spec admits the hang "could" happen on 24 and says the timeout covers it. It does not, so on Node 24 a hung file still holds the job until the 30-minute cancel. The spec needs a bound that works on 24 too, or must say plainly that 24 is not covered and get a ruling. Acceptance check 1 needs a probe per major, not "read the workflow". | |
| F3 | Minor | spec "Cause" bullet (cause must be in the PR, done-when 2) | spec.md "Cause"; test/lib/chrome.mjs:37-38 | The spec says "the dashboards' and Chrome's pipes keep the test process alive". Chrome survives only because nothing kills it (its `exit` hook never fires). The cause in the PR should name the right handles. | |

The helper should still run a step at once when it is registered after cleanup has started, and the spec should list this edge case. | |
