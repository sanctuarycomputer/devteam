# Hub tabs Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The hub at 127.0.0.1:4320 shows a tab per devteam instance (name + Inbox badge), each opening that instance's own dashboard in a frame, with one hub-level Inbox notification.

**Architecture:**
- `dashboard/hub.html` is rewritten: it keeps reading `instances.json` every 10 s and now renders a tab bar plus one lazily created `<iframe>` per instance.
- `scripts/devteam.mjs` sends a `frame-ancestors` on the dashboard page that allows only the dashboard itself and the hub, and the hub's CSP gains a `frame-src` listing the 25 instance ports.
- `dashboard/index.html` turns its own notifications off when framed.

**Tech Stack:** Node 18 built-ins, vanilla browser JS, `node:test`, and headless Chrome for the browser check.

**Spec:** `docs/superpowers/specs/2026-11-05-hub-tabs-design.md`

## Global Constraints

- Frames point at `http://127.0.0.1:<port>/`, the instance's own origin. No proxy, and nothing on the hub page acts for the owner.
- Dashboard `GET /` CSP: `frame-src 'self'; frame-ancestors 'self' http://127.0.0.1:<HUB_PORT> http://localhost:<HUB_PORT>`.
- Hub page CSP: `default-src 'none'; script-src 'unsafe-inline'; style-src 'unsafe-inline'; connect-src 'self'; frame-src <http://127.0.0.1:p for every p in PORT_RANGE>; frame-ancestors 'none'; base-uri 'none'; form-action 'none'`.
- Tabs are keyed by `root`. The URL hash is `#<name>`, or `#<name>-<6 hex of sha1(root)>` when two instances share a name.
- A gone instance keeps its tab, dimmed, for 30 s, then the tab and its frame are removed.
- Text is rendered only with `textContent`.
- Tests: `ASDF_RUBY_VERSION=3.1.7 ~/.asdf/installs/nodejs/<v>/bin/node --test test/kit.test.mjs`, Node 18.20.4 / 20.19.6 / 24.14.1, one at a time.

### Task 3: The tab bar

**Files:** Rewrite `docs/devteam/dashboard/hub.html`. Keep the token block verbatim between its markers.

- [ ] **Step 1: Write the page.** Structure:
  - `<header>`: the tab bar (`<nav id="tabs" role="tablist">`) and, at the right, the notify control (`<span id="notify">`).
  - `<main id="frames">`: one `<iframe>` per opened instance. Only the selected one is shown.
  - `<p id="empty">` for no instances.

  Behavior:
  - `instances` is a `Map` keyed by root, holding `{ x, tab, frame, goneAt }`.
  - `draw()` fetches `instances.json` (`cache: 'no-store'`). For each instance: create or update its tab (label `name`; badge `inbox` when it's a number above 0; `title` = root, kit, fleet mode and session count, or "starting"). Mark those not returned as gone (`goneAt` = now, class `gone`); drop any gone more than 30 s.
  - If an instance's port changed and its frame exists, set `frame.src` to the new `http://127.0.0.1:<port>/`.
  - `keyOf(x)` = `x.name`, or `${x.name}-${hex6}` when the name is shared, where `hex6` comes from `crypto.subtle.digest('SHA-1', root)`. Compute it once per root and cache it.
  - `select(key)`: set `location.hash` (`history.replaceState`), mark the tab `aria-selected`, create the frame on first select (`src = http://127.0.0.1:<port>/`, `title = name`), show it, and hide the others.
  - On first draw: select from `location.hash` if it matches, else the first instance with `inbox > 0`, else the first.
  - `hashchange` selects too.
  - Notify:
    - when `Notification` exists and the page is a secure context: a button (`Notify me of new Inbox items`), or the granted or blocked text, as the dashboard shows it;
    - keep `lastInbox` per root; after the first draw, when an instance's `inbox` rises, `new Notification(\`${name}: ${n} new in the Inbox\`)` with `onclick` focusing the window and selecting that tab.
  - Layout: a full-height flex column; the bar is about 36 px; the frame fills the rest (`border: 0; width: 100%; height: 100%`).
