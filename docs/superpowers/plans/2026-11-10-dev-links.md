# Dev links Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A session in a worktree runs its dev server and gets a link the owner can open from a Mac or an iPhone, behind the gateway's passkey session: `devteam.mjs preview <port>` (or `preview --run "<command>"`) prints `https://cool-tiger.<box>` on a box and `http://127.0.0.1:<port>` on a laptop, the Library lists it, a question can cite it, the gateway proxies it, and everything the kit started is stopped when the session goes.

**Architecture:**
- The kit (`docs/devteam/scripts/devteam.mjs`) gains a derived two-word name (`previewName`), a run-state record `run/previews/<name>.json`, the `preview` command family, `previews` in `/api/hello` (records read per request, liveness from a cache), a dashboard-only **preview tick** (probes, `down_since`, sweeps), Library rows, two owner actions (`preview-stop`, `preview-start`), a `preview` question-link kind, cleanup on `worker --remove`, `phase parked` and `handoff`, and a prompt line for a resumed worker.
- The dashboard page (`docs/devteam/dashboard/index.html`) gains a Previews group in the Library and renders `preview` links; it builds box URLs only when the gateway says it serves previews (`x-devteam-previews`).
- The gateway (`cloud/gateway.mjs`) recognises the name shape (a regex; no word lists), builds a name-to-port map from the hub's list it already polls (a doubly-listed name is **ambiguous**, never picked), looks a name up only after the session check with one coalesced hub refresh on a miss, proxies HTTP and WebSockets to `127.0.0.1:<port>` with `localhost:<port>` as `Host` and `Origin`, answers 503 (HTML to a navigation, plain otherwise) when a name is down, ambiguous or unknown, serves `/dev/`, names it in `box.json`, and marks `/api/data` with `x-devteam-previews: 1`. The image sets `ENV DEVTEAM_PREVIEWS=1`; `box-supervisors` skips `dev~` windows; the hub page links `/dev/`.
- A browser task drives Chrome over CDP against the whole chain on `http://box.localhost:<p>` before either PR counts as verified.

**Tech Stack:** Node 18 built-ins only (no dependencies), vanilla browser JS, `node:test`, tmux, Chrome (local verification only).

**Spec:** `docs/superpowers/specs/2026-11-10-dev-links-design.md` (approved, with the owner's decisions and the review's changes). Read it before any task.

## Global Constraints

- **Node 18+ built-ins only** in the kit and the gateway: no dependencies, no API newer than Node 18 (no `String.prototype.toWellFormed`, no `util.styleText`, no `Array.prototype.toSorted`). CI runs the matrix in `.github/workflows/test.yml`; locally run with Node 24 (`~/.asdf/installs/nodejs/24.21.0/bin/node`) and let CI cover the rest. The browser script may use Node 22+'s global `WebSocket` (it runs locally, under Node 24).
- **Harness-agnostic.** Everything an agent needs is a shell command, an environment variable or a tmux window. No hooks, no harness-specific files, no reliance on how Claude Code, Codex or OpenCode run background processes.
- **Nothing project-specific.** No framework names in code paths, only in help text and docs. The kit never reads a project's config to guess a port; the agent passes it or the kit picks one.
- **Fault-tolerant after a crash.** Every sweep and cleanup is idempotent and finishes what an interrupted run left: a record without its window, a `dev~*` window without its record, a tmux server that isn't there, a `run/previews/` that doesn't exist, a window id that now names another program's window (checked by name and start path before any kill). Records are written to a temp file and renamed; the tick writes one only when its mtime is what it read.
- **Reads stay reads.** `hello` is in `OPERATOR_READS` and `box-supervisors --status` runs it: it writes nothing and kills nothing. Probing and sweeping live in the dashboard's tick alone.
- **Names:** `PREVIEW_ADJECTIVES` and `PREVIEW_NOUNS` (kit only), 256 words each, lowercase `[a-z]{3,7}`, no word in both lists; `previewName(project, session, label)` = `${ADJ[h[0]]}-${NOUN[h[1]]}` with `h = sha256(`${project}\0${session}\0${label}`)`; `PREVIEW_NAME = /^[a-z]{3,7}-[a-z]{3,7}(?:-[1-9]\d?)?$/` in both files (the gateway needs only the shape).
- **Ports:** `previewPortOk(port, own)`: an integer, 1024–65535, not `HUB_PORT`, not in `PORT_RANGE`, not 7681, not `own` (the kit: `process.env.PORT` when `DEVTEAM_PUBLIC_URL` is set; the gateway: its listen port, passed into `createGateway({ port })`). Kit-picked ports come from 4400–4499.
- **Record:** `run/previews/<name>.json` as the spec's §1 shows; `run.window` is a tmux window id (`@12`); `label` at most 40 characters and one line (the registry's `oneLine` rule); at most 20 records per instance; `expires` = `at` + 7 days, renewed by every `preview <port>` / `--run` for that name; `down_since` set and cleared by the tick.
- **Hello:** `previews: [{ name, port, project, session, label, at, up, run }]`, records read per request, `up` from the tick's cache (`null` before the first probe), strings capped (`name` 63, `project` 63, `session` 80, `label` 40), at most 20, `run` a boolean. Nothing in `/api/hello` waits on a socket.
- **The box signals:** the kit prints a box URL only with `DEVTEAM_PUBLIC_URL` and `DEVTEAM_PREVIEWS=1` both set; the page builds one only with `x-devteam-previews: 1` on `/api/data`. Both are set only by the gateway's release.
- **Gateway:** preview hosts match `^[a-z]{3,7}-[a-z]{3,7}(?:-[1-9]\d?)?\.<box host>$`; `/healthz` answers only for non-preview hosts; checks in the spec's §4 order, the map lookup and the coalesced `refreshPreviews()` **after** the session check; upstream `Host: localhost:<port>`, `Origin: http://localhost:<port>` only when the browser's was the link's origin; `devteam_session` stripped; `mapLoop` maps `http://` and `ws://` forms of `localhost:<port>` and `127.0.0.1:<port>` for that link's port to the link's `https://`/`wss://` origin; `cache-control: no-store`; `x-frame-options` and `frame-ancestors` pass through; a framed load (`sec-fetch-dest` `iframe`, `frame`, `object`, `embed`, `fencedframe`) is 403 unless `sec-fetch-site` is `same-origin` or `same-site`; down, ambiguous and unknown answer 503 (HTML page with `refresh: 5` to `navigating(req)`, else `text/plain` with `retry-after: 5`); the gateway never picks between two claimants; 32 WebSockets per name; the gateway stores nothing about previews.
- **Tests first** in every task: write the failing test, run it to see it fail, then implement, then run it green, then the whole file.
- **Run tests:** `NODE=~/.asdf/installs/nodejs/24.21.0/bin/node`. Kit chain: `$NODE --test --test-concurrency=8 test/kit.test.mjs` (always the whole file: its steps are subtests of one test sharing a fixture, in order). Dashboard page: `$NODE --test --test-name-pattern "<text>" test/dashboard.test.mjs`. Gateway: `$NODE --test --test-name-pattern "<text>" test/gateway.test.mjs`. Browser: `$NODE test/browser/dev-links.mjs` (local, needs Chrome; not in CI). tmux in tests uses a private `TMUX_TMPDIR` (the chain already does; keep it).
- **Branches and commits.** Part A on `dev-links-kit`, Part B on `dev-links-gateway` (started after Part A merges, off `origin/main`; `cloud/box-supervisors` is also changed by #168, so take whatever is on main then). One release carries both, in that order. One commit per task; every commit message ends with a blank line then `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Never rebase or force-push.
- **Match the repo's style:** dense single-file code, comments that say why, no placeholders, no new files outside tests and docs (the browser script is a test).

## Decisions this plan makes where the spec leaves room

- **No word lists in the gateway.** The shape regex says a host is a preview's and the map says whether it is live; nothing else needed them, so the duplicated lists and their parity test are gone.
- **`PORT` goes in the window's command line** (`env PORT=… sh -c …`), not through `new-window -e`, so no tmux version matters.
- **A window id is trusted only with its name and start path.** Ids restart at `@0` with the tmux server, so `previewWindow(rec)` checks all three before any kill; an id that fails the check means the window is gone.
- **`start` kills a live window first** rather than refusing: an agent asking to start a preview wants it running, and one window per name is the invariant.
- **`down_since` is written only on an unchanged mtime**, so the tick never clobbers a `preview` command that ran between its read and its write; a skipped write happens on the next tick.
- **`phase parked` keeps records**, so `preview start` after a resume brings each back on the same name and port; only `worker --remove` and expiry remove them.
- **The lookup and the on-miss refresh come after the session check**, and the refresh is one promise shared by every waiter, so anonymous traffic can't make the gateway poll the hub, and a burst of misses costs one read.
- **Down, ambiguous and unknown are 503**, HTML only to `navigating(req)`, plain with `retry-after: 5` otherwise, so no dev client ever takes an error page for a successful fetch.
- **The gateway's `/healthz` is answered only for non-preview hosts**, so an app's own `/healthz` works through its link; the platform's probe arrives on the service's name.
- **The upgrade handler doesn't refresh on a miss**: the page that opened the socket already did, and an upgrade is not a navigation.
- **The browser script is a script, not a test file**, run by hand under Node 24 with Chrome; CI has no Chrome in its matrix and the chain's tests stay deterministic without it.
- **`cloud/box-supervisors` changes are one awk rule**, added to whatever #168 leaves on main at Part B's start.
