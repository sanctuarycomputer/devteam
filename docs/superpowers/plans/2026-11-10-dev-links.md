# Dev links Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A session in a worktree runs its dev server and gets a link the owner can open from a Mac or an iPhone, behind the gateway's passkey session: `devteam.mjs preview <port>` (or `preview --run "<command>"`) prints `https://cool-tiger.<box>` on a box and `http://127.0.0.1:<port>` on a laptop, the Library lists it, a question can cite it, the gateway proxies it, and everything the kit started is stopped when the session goes.

**Architecture:**
- The kit (`docs/devteam/scripts/devteam.mjs`) gains a derived two-word name (`previewName`), a run-state record `run/previews/<name>.json`, the `preview` command family, `previews` in `/api/hello`, Library rows, two owner actions (`preview-stop`, `preview-start`), a `preview` question-link kind, cleanup on `worker --remove`, `phase parked` and `handoff`, sweeps in the `hello` run, and a prompt line for a resumed worker.
- The dashboard page (`docs/devteam/dashboard/index.html`) gains a Previews group in the Library and renders `preview` links.
- The gateway (`cloud/gateway.mjs`) learns the name shape (its own copy of the word lists, parity-tested against the kit's), builds a name-to-port map from the hub's list it already polls, proxies HTTP and WebSockets to `127.0.0.1:<port>` with `localhost:<port>` as `Host` and `Origin`, serves three pages of its own (not answering, unknown, `/dev/`), and names the list page in `box.json`; the hub page (`docs/devteam/dashboard/hub.html`) links it.

**Tech Stack:** Node 18 built-ins only (no dependencies), vanilla browser JS, `node:test`, tmux.

**Spec:** `docs/superpowers/specs/2026-11-10-dev-links-design.md` (approved, with the owner's decisions). Read it before any task.

## Global Constraints

- **Node 18+ built-ins only** in the kit and the gateway: no dependencies, no API newer than Node 18 (no `String.prototype.toWellFormed`, no `util.styleText`, no `Array.prototype.toSorted`). CI runs the matrix in `.github/workflows/test.yml`; locally run with Node 24 (`~/.asdf/installs/nodejs/24.21.0/bin/node`) and let CI cover the rest.
- **Harness-agnostic.** Everything an agent needs is a shell command, an environment variable or a tmux window. No hooks, no harness-specific files, no reliance on how Claude Code, Codex or OpenCode run background processes.
- **Nothing project-specific.** No framework names in code paths, only in help text and docs. The kit never reads a project's config to guess a port; the agent passes it or the kit picks one.
- **Fault-tolerant after a crash.** Every sweep and cleanup is idempotent and finishes what an interrupted run left: a record without its window, a `dev~*` window without its record, a tmux server that isn't there, a `run/previews/` that doesn't exist. Records are written to a temp file and renamed. Nothing waits on a port for longer than its stated budget.
- **Names:** `PREVIEW_ADJECTIVES` and `PREVIEW_NOUNS`, 256 words each, lowercase `[a-z]{3,7}`, no word in both lists; `previewName(project, session, label)` = `${ADJ[h[0]]}-${NOUN[h[1]]}` with `h = sha256(`${project}\0${session}\0${label}`)`; `PREVIEW_NAME = /^([a-z]{3,7})-([a-z]{3,7})(?:-([1-9]\d?))?$/` and both words must be in their lists. The same lists and regex live in both files; a gateway test compares them with the kit's by reading the kit source, as `PUBLIC_TYPES` is compared today.
- **Ports:** `previewPortOk(port, { gatewayPort })`: an integer, 1024–65535, not `HUB_PORT`, not in `PORT_RANGE`, not 7681, not `gatewayPort` (the kit reads `process.env.PORT` only when `DEVTEAM_PUBLIC_URL` is set; the gateway knows its own). Kit-picked ports come from 4400–4499.
- **Record:** `run/previews/<name>.json` as the spec's §1 shows; `label` at most 40 characters and one line (the registry's `oneLine` rule); at most 20 records per instance; `expires` = `at` + 7 days, renewed by every `preview <port>` / `--run` for that name.
- **Hello:** `previews: [{ name, port, project, session, label, at, up, run }]`, strings capped (`name` 63, `project` 63, `session` 80, `label` 40), at most 20, `up` and `run` booleans.
- **Gateway:** preview hosts are `^${PREVIEW_NAME source without anchors}\.<box host>$`; upstream `Host: localhost:<port>`, `Origin: http://localhost:<port>` only when the browser's was the link's origin; `devteam_session` stripped; `mapLoop` maps `http://localhost:<port>` and `http://127.0.0.1:<port>` of that link's port to the link's origin; `cache-control: no-store`; `x-frame-options` and `frame-ancestors` pass through; a framed load (`sec-fetch-dest` `iframe` or `frame`) is 403 unless `sec-fetch-site` is `same-origin` or `same-site`; 32 WebSockets per name; the gateway stores nothing about previews.
- **Tests first** in every task: write the failing test, run it to see it fail, then implement, then run it green, then the whole file.
- **Run tests:** `NODE=~/.asdf/installs/nodejs/24.21.0/bin/node`. Kit chain: `$NODE --test --test-concurrency=8 test/kit.test.mjs` (always the whole file: its steps are subtests of one test sharing a fixture, in order). Dashboard page: `$NODE --test --test-name-pattern "<text>" test/dashboard.test.mjs`. Gateway: `$NODE --test --test-name-pattern "<text>" test/gateway.test.mjs`. tmux in tests uses a private `TMUX_TMPDIR` (the chain already does; keep it).
- **Branches and commits.** Part A on `dev-links-kit`, Part B on `dev-links-gateway` (started after Part A merges, off `origin/main`). One commit per task; every commit message ends with a blank line then `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Never rebase or force-push.
- **Match the repo's style:** dense single-file code, comments that say why, no placeholders, no new files outside tests and docs.

## Decisions this plan makes where the spec leaves room

- **The word lists live inline** in both `devteam.mjs` and `gateway.mjs` (no new file: the image copies only `gateway.mjs` and `hub.html`), with a parity test, as the artifact type map is handled.
- **`down_since`** is kept in the record by the sweep, so "24 h dead" survives a dashboard restart; it is cleared on the first successful probe.
- **A clash suffix is read back from this instance's own record** for the same (project, session, label) on every later `preview` for that link, so a link never changes name once the kit printed it, even if the other instance that caused the clash has gone.
- **`preview --run` refuses a command that contains a newline**, so the window's `sh -c` is one line a reader can see in `tmux list-windows -F '#{pane_start_command}'`.
- **The framing rule lives in `crossSiteOk`** (a preview-only branch), so every framed load is decided in the one place the gateway already decides cross-site loads.
- **`::1` is tried once**, only on `ECONNREFUSED` from `127.0.0.1`, for HTTP and WebSockets alike.
- **The hub's `Previews` link needs no new CSP entry**: it is a plain link that opens in the same tab on the box's own name.
